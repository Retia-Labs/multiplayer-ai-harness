## What to build

An authorized participant grants an invited teammate access to a project and enrolls that teammate's browser or desktop endpoint, allowing it to reconstruct shared task history. A seeded encrypted task is enough to verify this slice.

Type: **AFK**. Suggested work lane: **Collaboration/encryption**. Parent user stories: 3, 4, 9, 27, 30, 43.

## Acceptance criteria

- [ ] Login and a link alone do not establish cryptographic trust. A trusted endpoint or recovery authority completes the accepted endpoint-verification flow.
- [ ] Project-level access to existing shared history and future tasks is explained when granted. The teammate can decrypt ordered history and current pending state after joining late.
- [ ] Uninvited/unverified endpoints cannot read or control tasks through UI or direct requests. A copied private task link never carries decryption authority.
- [ ] Browser persistence, site-data loss and re-enrollment behavior are explicit and tested. Participant role and pending enrollment states are visible.
