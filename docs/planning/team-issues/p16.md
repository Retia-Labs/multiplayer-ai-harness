## What to build

Participants and the execution host recover from browser disconnection, network failure, host sleep, runtime crash and relay restart without losing context or blindly replaying actions.

Type: **AFK**. Suggested work lane: **Runtime/providers**. Parent user stories: 12, 16, 23, 24, 25.

## Acceptance criteria

- [ ] Persist enough event/command state to reconcile full prior history, provider lifecycle and pending approvals before controls re-enable.
- [ ] Distinguish host connectivity from task/turn outcome. Already-started actions may have continued; show their confirmed results or unknown state accurately.
- [ ] Accepted commands are deduplicated; invalid pending approvals expire. No automatic replay of arbitrary side-effecting commands after uncertain completion.
- [ ] Use an explicit supported provider resume path; otherwise show recovery-required with an actionable choice. Include reconnect, restart, stale response and crash-window acceptance scenarios.
