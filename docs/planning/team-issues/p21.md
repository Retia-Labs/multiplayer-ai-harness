## What to build

An authorized customer deletes task/project records and offboards access, with understandable live-storage, index, backup and participant-copy behavior.

Type: **AFK**. Suggested work lane: **Collaboration/encryption**. Parent user stories: 29, 30, 46.

## Acceptance criteria

- [ ] Remove deleted ciphertext and routing/index references from live stores; deny subsequent fetch/control requests and reflect deletion in authorized clients.
- [ ] Publish and implement a bounded backup retention/deletion policy before external release; service restore must not silently reactivate deleted memberships or control grants.
- [ ] Apply related access/key revocation without conflating history deletion with erasing participant-held plaintext or copies.
- [ ] Test unauthorized deletion, concurrent access, reconnect and restore paths; logs/support exports cannot resurrect deleted content.
