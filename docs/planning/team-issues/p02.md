## What to build

Build a desktop/runtime/browser experiment with an established encryption stack: verified endpoints exchange one encrypted task and authenticated control, recover on a clean endpoint, and remove a device. Deliver a reviewed protocol/library decision and threat model, not custom cryptography.

Type: **HITL**. Suggested work lane: **Collaboration/encryption**. Parent user stories: 17, 26, 27, 28, 29, 30, 48.

## Acceptance criteria

- [ ] The relay/database/logs cannot read task content or customer keys; document necessary cleartext metadata and browser/application-code and inference-provider trust boundaries.
- [ ] An existing trusted endpoint or customer recovery authority verifies new endpoint identity. Test substituted keys, modified controls, replayed approvals, and stale authorization.
- [ ] Demonstrate clean-endpoint recovery without operator secrets, history scope, membership/key rotation, and future-content exclusion for removed devices; recovery cannot reinstate expired action-approval grants.
- [ ] Demonstrate supported storage and packaging on both desktop platforms and browser. Record offline/revocation acknowledgment behavior, protocol versions, failure cases, and qualified review requirements. This proof is not a completed production security audit.
