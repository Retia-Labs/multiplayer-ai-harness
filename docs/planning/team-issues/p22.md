## What to build

Implement disclosed content-free measurement from actual endpoint/runtime outcomes, making setup failures, viewing/help, delivered intervention, task completion and returning-team behavior separately visible.

Type: **AFK**. Suggested work lane: **Desktop/product**. Parent user stories: 30, 33, 47.

## Acceptance criteria

- [ ] Count an activated person only after a qualifying task has two distinct participating humans and a non-initiator's intervention confirmed delivered; participation means task start or authenticated control/approval action.
- [ ] Do not count signup, passive views, help requests or queued-but-undelivered input as activation. Retry deduplication prevents duplicate person/task/event counts.
- [ ] Collect setup-stage outcomes, useful solo starts, invites, catch-up/help, direct control, completion and later-week team return without prompts, titles, paths, URLs, diffs or tool content.
- [ ] Compute/emit minimal events at authorized endpoints rather than inspecting relay plaintext. Implement disclosure, retention/deletion and a test path covering solo and two-person tasks; interviews are not required.
