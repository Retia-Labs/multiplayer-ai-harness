## What to build

A project owner removes access or revokes a device, and participants see the updated encryption/authorization state and each execution host's acknowledgment.

Type: **AFK**. Suggested work lane: **Collaboration/encryption**. Parent user stories: 17, 29, 30, 45.

## Acceptance criteria

- [ ] Advance authenticated membership/key state; removed endpoints cannot decrypt future content under the new state or authorize actions after host application.
- [ ] Show pending revocation for unreachable hosts. Reconcile current membership before enabling controls after reconnect; do not imply instant knowledge on an offline machine.
- [ ] Reject substituted identities, replayed grants and stale approval responses. Recovery cannot roll back current authorization.
- [ ] Explain that already-read plaintext and participant-held history cannot be erased; role, key and paid-seat state remain distinct.
