## What to build

An enrolled endpoint creates a task and reconstructs its content after reconnect through the hosted ciphertext relay. Use a fixture task to make this independently verifiable before connecting the real provider.

Type: **AFK**. Suggested work lane: **Collaboration/encryption**. Parent user stories: 8, 9, 24, 26, 30.

## Acceptance criteria

- [ ] Persist versioned opaque task/event records and encrypted objective, title, messages, plans, tool arguments/results, diffs and activity; cleartext metadata is explicitly enumerated.
- [ ] Ordered replay restores the full task rather than clearing history and applying only new events. Integrity failures and missing events are visible; duplicate delivery does not duplicate records.
- [ ] Content-derived server projections, search and file-overlap inspection are moved to authorized endpoints or disabled; no silent plaintext fallback.
- [ ] Canary content is absent from relay storage, logs and errors. The fixture-based client-to-relay-to-host acceptance path is reusable by later slices.
