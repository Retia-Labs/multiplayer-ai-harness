## What to build

A bounded integration proof connects two minimal clients to one real interactive Codex task on its execution host. Establish the supported provider/version/authentication contract before implementing the production adapter. Human involvement is limited to real test-account access and confirming the offered authentication arrangement; no customer interview is required.

Type: **HITL**. Suggested work lane: **Runtime/providers**. Parent user stories: 6, 8, 10, 11, 12, 13, 14, 15, 16, 25, 35, 48.

## Acceptance criteria

- [ ] Demonstrate real task start, streamed output, teammate input delivery, stale-turn rejection, interruption during tool work, one bounded approval resolution, and explicit provider resume. Record provider acknowledgments rather than UI-only success.
- [ ] Use unique command identities and prove retry deduplication. Distinguish one authoritative approval resolution from any claim of exactly-once external side effects after a crash.
- [ ] Exercise subscription and API modes separately using authorized test accounts. Document the usage owner and supported multi-human authority; technical login success is not proof of transferable entitlements.
- [ ] Pin the tested version, record platform prerequisites and capabilities, and provide a runnable acceptance harness and result matrix. A missing required capability produces a concrete supported alternative or blocker.
