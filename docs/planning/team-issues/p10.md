## What to build

The execution-host owner explicitly grants Bob action-approval rights; Bob resolves one real pending provider action while Alice sees the same decision and outcome.

Type: **AFK**. Suggested work lane: **Runtime/providers**. Parent user stories: 14, 15, 16, 17.

## Acceptance criteria

- [ ] Ordinary collaboration does not confer approval rights. The host validates the current verified actor, grant and exact task/turn/host/action before accepting a response.
- [ ] Show the exact pending action and its context. Two valid competing responses yield one recorded authoritative resolution; the losing client sees the existing actor and outcome.
- [ ] Reject mutated actions, replayed or expired responses, stale grants and stale requests after a restart. Deduplicate accepted dispatch without promising general exactly-once shell effects.
- [ ] Per-action approval is the default. Do not expose broad accept-for-session behavior without bounded, enforced and tested semantics.
