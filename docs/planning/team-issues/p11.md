## What to build

A task participant requests help or review from a named authorized project member. The recipient opens the exact task/question from an in-app inbox and explicitly resolves or cancels the request.

Type: **AFK**. Suggested work lane: **Desktop/product**. Parent user stories: 39, 40, 41.

## Acceptance criteria

- [ ] Persist an encrypted question, requester, recipient, task/context references and open/resolved/cancelled state; reject recipients outside the authorized project.
- [ ] Inbox and task views stay consistent across clients and reconnect. The recipient receives the catch-up context and can act later while host availability remains clear.
- [ ] Sending a help request produces no provider input or execution. Sending to the agent is a separate explicit action.
- [ ] No general chat, Slack or email integration is required. Any OS notification is generic and contains no decrypted task text.
