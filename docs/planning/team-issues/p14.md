## What to build

A customer restores the defined project/history and endpoint-trust scope using an existing trusted endpoint or customer-held recovery material, with no operator content-recovery path.

Type: **AFK**. Suggested work lane: **Collaboration/encryption**. Parent user stories: 27, 28, 30.

## Acceptance criteria

- [ ] Exercise recovery on a clean desktop/browser endpoint; wrong material fails, the operator sees only encrypted backups, and all-recovery-method loss is explained honestly.
- [ ] Protect persisted secrets using the selected supported desktop/browser storage and document site-data/locked-storage failure behavior.
- [ ] Recovery does not restore expired approval grants or provider credentials. Make the restored scope and trust transitions explicit.
- [ ] Provide an onboarding recovery exercise and supported replacement/rotation path; do not promise recovery after every trusted endpoint and recovery secret are lost.
